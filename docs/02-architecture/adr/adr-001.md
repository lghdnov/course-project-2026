# ADR-001: Выбор архитектурного паттерна

## Статус

Принято

## Контекст

Необходимо выбрать архитектурный паттерн для backend-системы социальной сети на Spring Boot. Система должна поддерживать: управление профилем, публикации, комментарии, групповые чаты, аутентификацию через Matrix OpenID.

## Рассмотренные варианты

| Паттерн | Плюсы | Минусы |
|---------|-------|--------|
| **MVC (Model-View-Controller)** | Простота, знакомство студентам | Смешение бизнес-логики и доступа к данным, сложно тестировать |
| **Layered (3-tier)** | Чёткое разделение слоёв | Жёсткая привязка к технологиям, сложно масштабировать |
| **Hexagonal (Ports & Adapters)** | Слабая связанность, тестируемость | Сложность внедрения для учебного проекта |
| **PCMEF** | 5 чётких слоёв, совместимость с Spring, проверенная практика | Требует адаптации под feature-first |

## Решение

Выбран **PCMEF (Presentation-Control-Mediator-Entity-Foundation)** с адаптацией под **feature-first архитектуру** и **гексагональные порты**.

## Обоснование

1. **Чёткое разделение ответственности** — пять строго определённых слоёв исключают дублирование функциональности и облегчают навигацию по коду.
2. **Однонаправленная зависимость** — каждый слой зависит только от нижележащего, что гарантирует отсутствие циклических связей и упрощает тестирование.
3. **Совместимость с Spring-экосистемой** — слои PCMEF естественным образом отображаются на стандартные аннотации Spring (`@RestController`, `@Service`, `@Repository`, `@Entity`).
4. **Возможность адаптации** — PCMEF допускает модификацию под конкретную предметную область (feature-first, гексагональные порты) без потери основных принципов.
5. **Проверенная практика** — паттерн широко применяется в enterprise-приложениях и имеет обширную документацию и сообщество.

## Последствия

- Код организован по бизнес-фичам, а не по техническим слоям
- Все межфичевые взаимодействия происходят через порты (интерфейсы)
- Каждая фича может быть протестирована изолированно
- При необходимости фича может быть вынесена в отдельный микросервис без рефакторинга бизнес-логики
